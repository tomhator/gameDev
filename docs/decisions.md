# 결정 로그

대화 원문은 남기지 않는다. 남기는 것은 **맥락 → 근거 → 결과** 세 줄이다.
새 항목은 **맨 위에** 붙인다. 지난 항목은 고치지 않는다 — 뒤집혔으면 새 항목에 "앞 항목을 뒤집음"이라고 적는다.
규칙은 CLAUDE.md 규약의 "결정 로그" 절. 티켓 안에서 끝난 결정은 티켓 댓글이 원본이고, 여기엔 세 줄 + `#번호`만 둔다.

```
## YYYY-MM-DD · 제목 (#티켓)
- 맥락: 무엇을 하다가 이 판단이 필요해졌나
- 근거: 무엇을 보고 그렇게 정했나 (버린 대안 포함)
- 결과: 무엇이 달라졌나 / 다음에 무엇을 하나
```

## 2026-09-11 · 첫 쁘띠 사이클은 rainy-day 하나, 나머지 둘은 보류 (#37)
- 맥락: #37(처마 투 처마)을 시작하려는데 규약 4조 "전작 출시 전 다음 시작 금지"에 drill-guard·football-xcom이 걸린다. 저장소 위치와 이름도 미정이었다.
- 근거: 두 프로젝트 모두 미출시인 채 멈춰 있어 "전작 출시"가 영영 안 온다. 완료(공개 URL) 하나를 만드는 쪽이 지표에 맞다. 폴더 동거(jigsaw-snap 방식) 대신 처음부터 별도 저장소 — 결정권자가 `tomhator/rainy-day`를 파기로 함.
- 결과: 프로젝트명 `rainy-day`. drill-guard·football-xcom은 README에 **보류**(새 티켓 없음, 재개는 rainy-day 공개 후). 사이클 티켓은 rainy-day 저장소로 옮기고 #37은 아이디어 대장으로 남는다.

## 2026-09-11 · 상세 기획 문서를 쓰지 않고 일요일에 토이부터 만든다 (#37)
- 맥락: 결정권자가 "이 아이디어 상세 기획을 진행해도 되나"라고 물었다. 일요일(9/13)에 기획~프로토타입~테스트를 한 번에 할 예정.
- 근거: `docs/knowhow.md` §1-3 — 문서가 코드를 앞지른 프로젝트는 전부 죽었다(메카 문서 83커밋 vs 코드 32, 스캐빈저 스펙 47편 중 플레이 검증 3회, helldiver 회의록 9편 1,444줄). §1-4의 유일하게 옳은 피벗은 "프로토를 하루 만들어 굴려본" 것. #37 다듬기 댓글의 완료 조건 7줄이 이미 기획의 전부다.
- 결과: 상세 기획 문서 없음. 9/13(일) 한 세션에 S1 토이 + 3바퀴 플레이 + 플레이 노트 3줄, **그 뒤에** 헌법 1장. 올림 9/23 · 공개 9/25는 그대로.

## 2026-09-10 · 대화 맥락은 원문이 아니라 세 줄로 남긴다 (#31)
- 맥락: 티켓 댓글 밖(터미널·클로드 앱 세션)에서 오간 논의를 어떻게 관리하느냐는 질문. 지금 규약이 붙잡는 채널은 티켓 댓글과 STATUS.md 둘뿐이고, 세션 대화는 끝나면 사라진다.
- 근거: 원문 transcript를 쌓으면 다음 세션이 읽을 양이 통제 불능이 되고, 로컬 memory는 환경마다 있고 없어서(Action 세션엔 없다) 진실의 소스로 못 쓴다. 필요한 건 "왜 그렇게 됐나"이지 대화 자체가 아니다. STATUS.md는 덮어쓰는 인수인계 메모라 누적 기록으로 부적합.
- 결과: `docs/decisions.md` 신설 — 맥락→근거→결과 세 줄을 맨 위에 append. 세션 시작에 최근 10개를 읽고 세션 끝에 적는다. 규약에 "결정 로그" 절 추가.

## 2026-09-10 · 티켓에 단계 6개와 동시 진행 제한을 붙인다 (#31)
- 맥락: 티켓이 "무엇인가"(종류 라벨)만 있고 "어디까지 왔나"가 없어서, 여러 개가 동시에 반쯤 굴러가다 아무것도 안 끝났다.
- 근거: #20 부검이 지목한 실패 모드는 크리티컬 패스를 아트가 막는 것과 동시 진행 과다. 상한을 숫자로 못박아야 "자리가 없다"가 판단이 아니라 사실이 된다. 8세션 사이클에 셋 이상은 안 끝난다는 관측치.

## 2026-09-10 · 완료의 정의를 "공개 URL + 타인 플레이"로 바꾼다 (#20)
- 맥락: 14개 시작, 0개 출시. 그레이박스 완성을 완료로 세고 있었다(`docs/knowhow.md` §1).
